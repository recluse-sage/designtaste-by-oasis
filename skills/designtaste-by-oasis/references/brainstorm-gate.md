# Brainstorm Gate (mandatory Step 1)

Brainstorming always runs first. NEVER proceed without explicit user
approval. Only proceed when requirements met.

## Gate checklist

All boxes must be checked before leaving Step 1:

- [ ] Written brief exists: goal, audience, and scope stated.
- [ ] Architecture input file received and reviewed, OR missing-arch
      ask completed (see below).
- [ ] User gave explicit approval of the brief (a "yes / approved"
      message, not silence or implication).
- [ ] Open questions recorded (deferred items listed, not resolved
      by guessing).

## NEVER-proceed wording

Use this exact stance with the user:

> "Brainstorming is mandatory Step 1. I NEVER proceed without your
> explicit approval. Only proceed when requirements met."

If the user tries to skip, block and re-invoke this step with a
clear message, e.g.:

> "Blocked: brainstorming is not done yet. Please review the brief
> above and reply with approval or changes. I cannot continue to
> layout until you approve."

An expected block is not a silent pass: always say what is missing
and what reply unblocks.

## Missing-arch ask behavior

If the architecture input file is missing:

1. Stop. Do not hallucinate structure.
2. Ask for it: what file or description defines the site/app
   structure, and where to find it.
3. Offer a minimal alternative: user pastes a short outline
   (pages/sections in 5-10 lines) to proceed.
4. Record that the outline is user-provided, not inferred.

Only proceed when requirements met: brief + input (or substitute)
+ explicit approval.
